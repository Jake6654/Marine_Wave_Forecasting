# KST 원본 재처리 기록

## 확인 근거와 범위

2026-10-23 사용자가 다운로드한 해양기상부이 시간 자료의 원본 시간대를
KST라고 확인해 전달했다. 확인 경로와 공식 답변 원문은 아직 첨부되지 않았다.
이번 기록은 사용자 보고를 근거로 하며, 프로그램이 공식 답변을 직접 조회하거나
CSV 자체에서 시간대를 자동 판별했다는 뜻은 아니다.

메타데이터의 `source_timezone_status="confirmed"`는 이 호출자 보고를 반영한다.
`source_timezone_confirmation_method="caller_reported"`와
`source_timezone_evidence`를 함께 기록해 근거 수준을 구분한다.
근거 인자를 생략하면 기존처럼 `caller_supplied_unverified`를 유지한다.

## 데이터 흐름

```text
CP949 원본: 2025-01-01 00:00 (시간대 표기 없음)
→ Asia/Seoul로 해석: 2025-01-01 00:00+09:00
→ UTC로 변환: 2024-12-31 15:00+00:00
→ UTF-8 CSV와 처리 메타데이터를 별도 저장
```

원본은 `data/preview/OBS_BUOY_TIM_20261021192756.csv`다.
새 결과는 `data/processed/buoy_22101_2025_kst_to_utc.csv`와
같은 이름의 `.metadata.json`이다. 원본 및 기존 `utc_assumed` 결과는 보존한다.
기존 결과는 과거 가정의 재현용이며 현재 학습 스크립트의 기본 입력이 아니다.

## 재현 명령

프로젝트 루트에서 실행한다. 출력 파일이 있으면 덮어쓰지 않고 실패한다.
다시 생성하려면 다른 출력 이름을 선택한다.

```bash
uv run --locked python scripts/prepare_data.py \
  --input data/preview/OBS_BUOY_TIM_20261021192756.csv \
  --output data/processed/buoy_22101_2025_kst_to_utc.csv \
  --source-timezone Asia/Seoul \
  --source-timezone-evidence "2026-10-23 사용자가 원본 시간대를 KST라고 확인해 전달함. 공식 답변 원문 미첨부."
```

실제 생성 시에는 같은 의미의 더 상세한 근거 문장을 기록했다.

## 한국 날짜 기준 분할

| 구간 | 기준시각 범위(KST) | 정답 시각 제한 |
| --- | --- | --- |
| 학습 | 2025-10-01 00:00 전 | 10월 1일 00:00 전 |
| 검증 | 2025-10-01 00:00 이상, 2025-12-01 00:00 미만 | 12월 1일 00:00 전 |
| 최종 테스트 | 2025-12-01 00:00 이상, 2026-01-01 00:00 미만 | 2026년 1월 1일 00:00 전 |

호출부는 `+09:00`을 명시하고 `split_by_time()`이 UTC로 변환한다.
예를 들어 10월 1일 00:00 KST 경계는 9월 30일 15:00 UTC다.
경계를 넘는 6시간 후 정답은 기존 로직대로 제외한다.

## 영향과 비영향

- 절대 시각은 기존 UTC 가정보다 9시간 앞선 실제 UTC 시각으로 정정된다.
- 관측 수치·결측값은 그대로 보존한다. 보간이나 행 추가는 하지 않는다.
- 정확한 1·3·6시간 전 특성과 6시간 후 정답 연결 로직은 변경하지 않는다.
- 관측과 분할 경계를 함께 9시간 이동하므로 기존 실험과 동일한 표본 구성이 유지된다.
- 최종 테스트의 구성·시간 경계 검사는 하지만, 테스트 성능으로 모델을 선택하지 않는다.
- 새 시간대 근거는 향후 공식 답변 원문을 확보하면 보강할 수 있다.
