# Marine Wave Forecasting

### 공개 해양기상 데이터 기반 6시간 후 유의파고 예측 서비스

기상청의 덕적도 부이 관측자료로 **현재 바다 상태를 확인하고, 6시간 뒤의 파고를 예측하는 개인 프로젝트**입니다.

해군 빅데이터 분석병 지원을 준비하며 해양 데이터를 직접 다뤄보고,
분석 결과를 실제로 확인할 수 있는 서비스까지 만들어보고자 시작했습니다.
데이터 정리부터 모델 비교, 최신 관측 수집, API와 웹 화면 배포까지 연결했습니다.

[서비스 바로가기](https://marine-wave-forecasting.vercel.app) · [API 문서](https://marine-wave-forecasting.onrender.com/docs)

> 학습·시연용 실험 서비스입니다. 공식 기상예보나 운항 안전 판정이 아니며,
> 실제 항해·임무 수행 여부를 결정하는 데 사용하면 안 됩니다.
> 무료 서버가 쉬고 있다면 첫 조회가 늦거나 실패할 수 있습니다. 잠시 뒤 새로고침해 주세요.

## 무엇을 할 수 있나요?

- **현재 관측 확인:** 덕적도의 유의파고·풍속·기압과 관측시각을 보여줍니다.
- **6시간 후 파고 예측:** 저장된 RandomForest 모델로 예상 유의파고를 계산합니다.
- **관측자료 자동 갱신:** 서버 시작 시 최근 12시간 자료를 수집하고, 실행 중에는 수집 완료 후 10분 간격으로 갱신합니다.
- **자료 상태 안내:** 관측이 오래됐거나 필요한 자료가 부족하면 예측값 대신 이유를 표시합니다.
- **모의 파고 구간 표시:** 예측값을 P1~P4 구간으로 나눠 보여줍니다. 운항 위험 등급은 아닙니다.

현재 대상은 **덕적도 관측소 한 곳(22101)**입니다.
웹의 일반 새로고침은 저장 자료를 다시 읽습니다.
수동 수집 API와 버튼도 구현했지만, 공개 Vercel의 수집 버튼은 로컬 출처 제한이 남아 있어 아직 사용할 수 없습니다.

## 무엇을 예측하나요?

예측 대상은 **기준 관측시각으로부터 정확히 6시간 뒤 한 시점의 유의파고(m)**입니다.

예를 들어 18시 관측을 기준으로 한다면 다음 날 00시의 파고를 예측합니다.
현재부터 6시간 동안의 최대 파고나 사고 발생 확률을 예측하는 것은 아닙니다.

화면의 최신 관측과 예측 기준시각은 다를 수 있습니다.
최신 관측에는 30분 자료도 표시하지만, 모델은 정시 관측을 사용하므로 두 시각을 구분해 보여줍니다.

## 가장 중요했던 문제: 빠진 시간의 데이터

관측 기록에는 빠진 시각이 있었습니다.
예를 들어 09시 다음 기록이 11시라면, 이전 행을 그대로 사용해도 그것은 ‘1시간 전’의 관측이 아닙니다.

```text
09:00 관측 있음 → 10:00 관측 없음 → 11:00 관측 있음

11시의 이전 행은 09시 기록
하지만 11시의 1시간 전 자료는 없음
```

이 문제를 해결하기 위해 **행 순서가 아닌 관측소와 실제 시각을 기준으로 자료를 연결**했습니다.

- 정확한 1·3·6시간 전 파고를 찾아 예측 입력으로 사용합니다.
- 정확히 6시간 뒤의 관측값을 학습 정답으로 연결합니다.
- 필요한 시각의 자료가 없다면 다른 시간의 값으로 대신하지 않습니다.
- 학습에는 필요한 입력·정답이 모두 있는 표본을 사용하고, 서비스에서는 입력이 부족하면 예측을 차단합니다.
- 원본 시각은 KST로 해석하고, 내부 계산에서는 UTC로 통일합니다.

이 과정을 통해 모델을 학습시키는 것만큼 **데이터의 시간 관계를 올바르게 맞추는 일**이 중요하다는 것을 배웠습니다.

## 데이터와 모델

### 사용 데이터

- 출처: 기상청 기상자료개방포털의 해양기상부이 시간 자료
- 과거 자료: 덕적도 2025년 관측 8,043건
- 최신 자료: 기상청 API허브의 해양기상부이 관측 API
- 현재 모델 입력: 현재 유의파고·풍속·기압, 1·3·6시간 전 파고, 1시간 파고 변화량

원본 데이터의 행 수와 실제 학습 표본 수는 다릅니다.
과거·미래 관측을 연결한 뒤 결측과 시간 경계를 확인해 다음과 같이 분리했습니다.

| 구간 | 기간(KST) | 표본 수 | 용도 |
| --- | --- | ---: | --- |
| 학습 | 2025년 1~9월 | 3,891 | 모델 학습 |
| 검증 | 2025년 10~11월 | 1,130 | 모델 비교·선택 |
| 테스트 | 2025년 12월 | 728 | 최종 평가용 분리 구간 |

시간 순서대로 나누고, 정답 시각이 다음 구간으로 넘어가는 표본은 이전 구간에서 제외했습니다.
아래 검증 결과와 별도로, 모델 선택 후 12월 테스트 구간에서도 최종 평가했습니다.

### 왜 “지금 파고가 6시간 뒤에도 같을 것”을 비교 기준으로 삼았나요?

머신러닝 모델이 예측값을 만든다는 사실만으로 그 모델이 유용하다고 할 수는 없습니다.
**학습 없이 사용할 수 있는 간단한 방법보다 실제로 오차를 줄이는지** 먼저 확인해야 합니다.

이 프로젝트에서는 현재 파고를 그대로 미래 예측값으로 사용하는 **현재값 유지(Persistence)**를
비교 기준으로 삼았습니다. 바다 상태가 단시간에 크게 달라지지 않는 경우에는 이 방법도
꽤 잘 맞을 수 있어, 모델의 추가적인 가치를 확인하기에 적합한 출발점입니다.
6시간 동안 파고가 항상 유지된다는 뜻은 아닙니다.

예를 들어 현재 파고가 1.0m라면 다음과 같이 비교합니다.

- 기준 방법은 별도 학습 없이 6시간 뒤에도 **1.0m**라고 예측합니다.
- 머신러닝 모델은 현재 파고뿐 아니라 풍속·기압·과거 파고를 함께 보고 예측합니다.
- 6시간 뒤 실제 관측과 각 예측값을 비교해 어느 쪽의 오차가 작은지 확인합니다.

동일한 검증 시각과 실제 관측값으로 비교해야 공정합니다.
현재값 유지보다 좋아지지 않는다면, 더 복잡한 모델을 사용하는 이유부터 다시 검토해야 합니다.

### Ridge는 어떤 모델인가요?

**여러 입력에 중요도를 부여해 하나의 계산식으로 예측하는 모델**입니다.
기본적인 선형회귀에, 특정 입력의 영향이 지나치게 커지지 않도록 제약을 더한 방식입니다.

```text
예상 파고 = 현재 파고 × 가중치
          + 풍속 × 가중치
          + 기압 × 가중치
          + 과거 파고 등의 영향
          + 기본 보정값(절편)
```

가중치는 각 입력이 예측에 얼마나 영향을 주는지를 나타내는 숫자입니다.
사람이 하나씩 정하는 것이 아니라, 모델이 과거 입력과 실제 정답을 비교하며 학습합니다.
이 프로젝트에서는 단위가 다른 입력을 비슷한 척도로 맞춘 뒤 학습했습니다.

Ridge의 장점은 구조가 단순하고 각 입력의 영향을 살펴보기 쉽다는 점입니다.
다만 기본적으로 입력을 가중합하는 방식이므로,
**같은 풍속이라도 다른 바다 상태에 따라 영향이 달라지는 복잡한 관계**는
현재와 같은 단순 입력 구성만으로 충분히 표현하기 어려울 수 있습니다.
제약을 둔다고 새로운 데이터에서도 항상 잘 맞는 것은 아닙니다.

### RandomForest는 어떤 모델인가요?

**여러 개의 결정트리가 각각 예측한 값을 평균해 최종 예측을 만드는 모델**입니다.
결정트리는 입력값에 대한 질문을 차례로 나누며 비슷한 과거 상황을 찾는 방식으로 이해할 수 있습니다.

예를 들어 다음과 같은 질문으로 상황을 나눌 수 있습니다.

```text
현재 파고가 일정 높이보다 큰가?
→ 풍속도 강한가?
→ 1시간 전보다 파고가 상승했는가?
→ 이 조건에 해당했던 학습 자료의 정답을 바탕으로 예측
```

이는 원리를 설명하기 위한 예시이며 실제 학습된 트리에서 추출한 규칙은 아닙니다.

하나의 트리만 사용하면 일부 학습 자료에 지나치게 맞춰질 수 있습니다.
RandomForest는 자료와 입력을 조금씩 다르게 사용한 여러 트리의 결과를 모읍니다.
이 프로젝트의 배포 모델은 **200개 트리의 예측을 평균**합니다.

Ridge와 달리 **여러 조건의 조합에 따라 결과가 달라지는 관계**를 별도 계산식 없이
학습할 수 있다는 장점이 있습니다. 반면 하나의 간단한 식으로 설명하기 어렵고,
학습에서 드물게 보거나 보지 못한 높은 파고까지 잘 예측한다고 보장할 수는 없습니다.

### 실제 비교 결과

**검증 데이터 1,130개 표본 기준**입니다.

| 모델 | 평균 절대오차 MAE(m) | RMSE(m) |
| --- | ---: | ---: |
| 현재값 유지(Persistence) | 0.2237 | 0.3265 |
| Ridge | **0.1926** | 0.2809 |
| RandomForest | 0.1928 | **0.2736** |

MAE는 예측과 실제 값의 차이를 절댓값으로 평균한 수치이고,
RMSE는 큰 오차의 영향을 더 크게 반영합니다. 둘 다 작을수록 좋습니다.

배포 모델인 RandomForest는 기준 방법 대비 **MAE 약 13.8%, RMSE 약 16.2%를 줄였습니다.**
이는 검증 데이터의 결과이며, 정확도 퍼센트나 실제 운항 안전성 개선을 의미하지 않습니다.

### 이 프로젝트에는 어느 모델이 더 적합했나요?

**이번 검증 결과에서는 RandomForest를 첫 배포 모델로 선택했습니다.**
복잡한 모델이라서 선택한 것이 아니라 다음 결과를 함께 확인했기 때문입니다.

1. **평균적인 오차는 거의 비슷했습니다.** 전체 MAE는 Ridge가 조금 더 작았지만,
   차이는 약 0.000235m에 불과해 이 수치 하나만으로 뚜렷한 우열을 주장하지 않았습니다.
2. **큰 오차에 더 영향을 받는 RMSE는 RandomForest가 낮았습니다.**
   전체 RMSE는 Ridge보다 약 2.6% 낮았습니다.
3. **상대적으로 높은 파고 구간에서도 오차가 더 작았습니다.**
   실제 파고가 1.0m 이상인 검증 표본 233개에서 MAE는
   Ridge 약 0.386m, RandomForest 약 0.346m로, RandomForest가 약 10.3% 낮았습니다.

여기서 1.0m는 학습 자료의 분포를 보고 정한 분석용 기준이며 공식 위험 기준이 아닙니다.
높은 파고 구간은 예측이 끝난 뒤 실제 정답으로 나눠 성능을 살펴본 것이고,
미래 실제 파고를 모델 입력으로 사용한 것은 아닙니다.

정리하면 **단순하고 해석하기 쉬운 Ridge도 경쟁력 있는 모델이었지만,
평균 오차가 비슷한 상황에서 전체 RMSE와 높은 파고 구간의 결과를 추가 근거로 삼아
RandomForest를 선택**했습니다.
이는 덕적도 한 지점의 해당 검증 구간에서 내린 선택이며,
RandomForest가 모든 해역·기간에서 더 좋다는 의미는 아닙니다.
선택한 모델도 높은 파고 구간에서 실제보다 낮게 예측하는 경우가 남아 있어
운항 안전 판단에 사용할 수는 없습니다.

자세한 설정과 선택 근거는 [모델 비교·선택 기록](docs/model_selection.md)에 정리했습니다.

### 선택 후 최종 테스트 결과

2026-10-26, 선택한 모델과 설정을 바꾸지 않고 **2025년 12월 테스트 표본 728개**를 평가했습니다.
학습+검증을 합쳐 재학습하거나 테스트 결과로 모델을 다시 선택하지 않았습니다.

| 방법 | MAE(m) | RMSE(m) |
| --- | ---: | ---: |
| 현재값 유지 | 0.2533 | 0.3555 |
| RandomForest | **0.2103** | **0.2969** |

현재값 유지 대비 MAE는 약 **17.0%**, RMSE는 약 **16.5%** 낮았습니다.
다만 실제 파고 1.0m 이상인 209개 표본에서는 약 **76.1%를 실제보다 낮게 예측**했습니다.
오차가 줄었다는 것과 안전하게 예측한다는 것은 다르며, 이 한계도 결과에 함께 기록했습니다.
이는 과거자료의 독립 테스트 구간 평가이며, 실시간 예측을 사전 저장해 비교한 운영 평가는 아닙니다.

실행 방법·표본별 예측·한계는 [최종 테스트 보고서](docs/final_test_2025_12.md)를 참고하세요.

## 서비스는 어떻게 동작하나요?

```text
기상청 최신 관측
    ↓
응답 검사·SQLite 저장
    ↓
관측 상태 확인·예측 입력 생성
    ↓
저장된 RandomForest로 예측
    ↓
FastAPI(Render) → Next.js 대시보드(Vercel)
```

모델은 요청할 때마다 학습하지 않고, 미리 학습한 파일을 불러와 사용합니다.
수집이 실패하면 서버와 기존 자료를 유지하고 다음 주기에 다시 시도합니다.
단, 기존 자료가 오래됐다면 예측은 차단합니다.

| 구분 | 사용 기술 |
| --- | --- |
| 데이터 처리 | Python, pandas |
| 머신러닝 | scikit-learn, Ridge, RandomForest |
| 관측 저장 | SQLite |
| 백엔드 | FastAPI, Uvicorn |
| 프론트엔드 | Next.js, React, TypeScript |
| 검증 | pytest, 프론트엔드 테스트 |
| 환경·배포 | uv, Render, Vercel |

## 로컬에서 실행하기

### 1. Python 환경 준비

배포 모델의 환경 검사에 맞춰 Python **3.13.5**를 사용합니다.
프로젝트 루트에서 실행합니다.

```bash
uv sync --locked --python 3.13.5
cp -n .env.example .env
```

이미 있는 `.env`는 덮어쓰지 않습니다.
파일을 열어 `KMA_API_KEY`에 본인의 기상청 인증키를 입력합니다.
키를 Git에 커밋하지 마세요.

### 2. API와 자동 수집 실행

아래 설정은 **저장소에 포함된 직접 만든 모델로 실험 예측을 실행할 때만** 사용합니다.
출처를 모르는 pickle 모델을 내려받아 신뢰 설정을 켜면 안 됩니다.

macOS/Linux 터미널에서:

```bash
set -a
source .env
set +a

export MARINE_API_MODEL_PATH=deployment/models/rf_22101_v1
export MARINE_API_TRUST_LOCAL_MODEL=true
export MARINE_API_ALLOW_UNVERIFIED_SOURCE=true
export MARINE_API_BACKGROUND_COLLECTION=true

uv run --locked uvicorn marine_forecast.api.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

관측 수집은 HTTP 시작을 기다리게 하지 않고 백그라운드에서 진행합니다.
첫 수집이 끝나기 전에는 조회가 준비되지 않았을 수 있습니다.
별도의 반복 수집기를 동시에 실행하지 마세요.

- API 문서: `http://127.0.0.1:8000/docs`
- 서버 실행 확인: `http://127.0.0.1:8000/health/live`
- 모델·저장소 준비 확인: `http://127.0.0.1:8000/health/ready`

### 3. 프론트엔드 실행

Node.js 22 이상이 필요합니다. 별도 터미널에서:

```bash
cd frontend
npm ci
cp -n .env.example .env.local
npm run dev
```

`frontend/.env.local`의 조회 주소를 다음과 같이 설정합니다.

```dotenv
MARINE_API_BASE_URL=http://127.0.0.1:8000
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다.
기상청 인증키는 프론트엔드 환경 파일에 넣지 않습니다.
선택적인 로컬 수동 수집은 [수동 수집 설정](docs/manual_collection.md)을 참고하세요.

## 테스트

백엔드:

```bash
uv run --locked pytest -q
```

프론트엔드:

```bash
cd frontend
npm test
npm run typecheck
```

테스트 통과와 실제 외부 시스템 검증은 구분합니다.
모델·데이터·API 연결은 로컬 테스트와 별도로 실제 Render 및 Vercel 화면에서 확인했습니다.
무료 서버의 장기 실행·슬립 후 복구까지 모두 검증된 것은 아닙니다.

과거 테스트 개수는 현재 소스의 결과를 대신하지 않습니다.
변경 후 위 명령으로 다시 확인하고, 검증 당시의 상세 기록은 각 문서를 참고하세요.

## 현재 상태와 한계

- 최신 관측 수집부터 예측·API·웹 화면까지 구현하고 Vercel과 Render를 연결했습니다.
- 단일 관측소·한 해 자료 중심의 실험이며, 다른 해역과 연도에서의 성능을 보장하지 않습니다.
- 높은 파고 구간에도 과소예측이 남아 있습니다.
- 품질관리 코드(AQC·MQC)의 위치별 해석은 확정하지 않았으며, 자료를 QC 승인 상태로 표현하지 않습니다.
- API 기압과 학습 CSV 기압의 수치 일치는 덕적도 2025년 정시 8,043건에 대한 사용자 제공 결과로 기록했습니다. 다른 기간·지점까지 검증한 것은 아닙니다.
- P1~P4는 예측 파고를 구분한 모의 구간이며, 사고 확률이나 운항 가능 여부가 아닙니다.
- 무료 Render가 멈추면 수집도 멈춥니다. 임시 DB가 사라지면 시작 시 최근 관측을 재수집하는 구조입니다.
- 재시작 후 복구와 장기 실행은 추가 검증 대상이며, 무료 서버의 첫 응답은 지연될 수 있습니다.
- 공개 수동 수집 기능의 사용자 인증·권한·출처 설정과 cold start 대기 화면은 후속 과제입니다.
- 자동 재학습, 72시간 예측, 다중 관측소 지원은 포함하지 않았습니다.

## 폴더 구조

```text
src/marine_forecast/  데이터 처리·특성 생성·학습·추론·API
scripts/             자료 준비·모델 내보내기·관측 수집 도구
tests/               Python 테스트
frontend/            Next.js 대시보드와 프론트엔드 테스트
deployment/models/   배포에 포함하는 학습 모델·메타데이터
data/                원본·가공 자료 및 로컬 관측 DB
docs/                설계·학습·검증·배포 기록
```

실제 키와 토큰, 로컬 실시간 DB, 가상환경은 Git에서 제외합니다.
배포용 모델 파일은 `deployment/models/`에 별도로 포함합니다.
