# Marine Wave Forecasting

공개 해양기상 관측자료를 이용한 6시간 뒤 유의파고 예측 프로젝트.

현재 연간 자료는 원본 시각을 KST로 해석하고 내부 저장은 UTC를 사용한다.
학습 스크립트는 `buoy_22101_2025_kst_to_utc.csv`를 사용한다.
데이터 재생성 방법과 확인 근거는 [KST 재처리 기록](docs/kst_reprocessing.md)을 참고한다.

실시간 관측의 1회·반복 수집, SQLite 저장 및 Docker Compose 운영 방법은
[수집기 운영 안내](docs/collector_operations.md)를 참고한다.
수집 구현과 모델의 실시간 추론·QC 검증 완료는 서로 다른 상태다.

모델 저장·재로딩과 최근 관측의 6시간 뒤 **실험 예측**은
[Phase F–G 구현·실행 안내](docs/live_prediction.md)를 참고한다.
QC·기압 의미가 미확인이라 기본 예측은 차단되며 명시적 실험 옵션에서만 실행된다.

## 1. 프로젝트 목적

데이터 수집, 탐색적 분석, 머신러닝 학습, 성능 검증, 웹 서비스 배포를
직접 구현하면서 각 과정의 원리와 한계를 이해한다.

첫 버전은 관측지점 한 곳을 대상으로 한다.
관측지점과 데이터 기간은 실제 자료의 제공 범위와 품질을 확인한 뒤 확정한다.

## 2. 예측 문제

예측 기준시각 t까지 이용할 수 있는 관측자료로,
같은 관측지점의 t + 6시간 유의파고를 예측한다.

- 예측 대상: 유의파고
- 단위: 미터(m)
- 예측 시간 간격: 6시간
- 초기 관측지점 수: 1곳
- 목표 데이터 간격: 1시간
- 문제 유형: 연속적인 수치를 예측하는 회귀 문제

예측 대상은 정확히 6시간 뒤 시점의 유의파고다.
현재부터 6시간 동안의 최대 파고를 예측하는 것은 아니다.

### 예시

- 예측 기준시각: 2025-01-10 09:00 KST
- 예측 대상시각: 2025-01-10 15:00 KST
- 입력: 09:00까지 이용할 수 있는 관측자료
- 출력: 15:00의 예상 유의파고(m)
- 정답: 실제로 관측된 15:00의 유의파고(m)

위 날짜와 시각은 문제 설명용 예시이며, 확보한 데이터 범위를 뜻하지 않는다.

## 3. 데이터와 입력 변수

우선 기상청 해양기상부이 관측자료를 검토한다.
제공 항목, 단위, 시간대, 결측값 표기와 품질정보는 실제 명세와 샘플로 확인한다.

입력 후보는 다음과 같다.

- 현재 및 과거의 유의파고
- 현재 및 과거의 풍속
- 풍향, 기압 등 추가 관측 요소
- 과거 관측값으로 계산한 변화량과 이동평균

모든 입력 후보를 반드시 사용하는 것은 아니다.
실제 자료의 가용성과 검증 결과를 바탕으로 선택한다.

과거 자료를 몇 시간까지 사용할지는 후속 실험에서 정한다.

## 4. 데이터 사용 원칙

- 원본 자료와 가공한 자료를 구분해서 보관한다.
- 자료의 출처, 수집 범위와 전처리 과정을 기록한다.
- 시간대를 명시하고, 시간 비교 전에 일관된 기준으로 변환한다.
- 결측값과 비정상 값의 처리 이유를 기록한다.
- 예측 시점 이후의 실제 관측값을 입력에 사용하지 않는다.
- 6행 뒤가 아니라, 정확히 6시간 뒤 시각의 관측값을 정답으로 연결한다.

초기 과거 실험에서는 관측시각을 기준으로 자료를 사용할 수 있다고 가정한다.
실시간 서비스에서는 실제 수신 시각과 자료 갱신 지연도 고려한다.

## 5. 기준 모델과 평가 방법

### 기준 모델

첫 비교 대상은 현재값 유지 모델이다.

현재의 유의파고가 6시간 뒤에도 그대로 유지된다고 예측한다.

현재 유의파고가 1.2m라면, 기준 모델의 6시간 뒤 예측값도 1.2m다.

### 데이터 분리

시간 순서에 따라 학습, 검증, 시험 데이터를 구분한다.

- 학습 데이터: 모델의 관계를 학습하는 데 사용
- 검증 데이터: 입력 변수, 모델과 설정을 선택하는 데 사용
- 시험 데이터: 선택이 끝난 모델의 최종 평가에 사용

시험 데이터의 결과를 반복해서 보면서 모델을 선택하지 않는다.
분할 경계에서는 학습에 사용한 정답 시각이 평가 구간을 침범하지 않도록 확인한다.

### 평가 지표

- MAE: 예측 오차의 절댓값을 평균한 값
- RMSE: 큰 오차에 더 큰 영향을 받는 평가 지표

두 지표 모두 단위는 m이며, 같은 평가 데이터에서 값이 작을수록 오차가 작다.

전체 오차와 함께 높은 파고 구간의 과소예측도 별도로 분석한다.
높은 파고 구간의 정의는 최종 시험 평가 전에 정한다.

모든 모델은 동일한 평가 시점과 정답을 기준으로 비교한다.

## 6. 첫 버전의 결과물

- 실제 관측자료의 수집 또는 로딩 코드
- 데이터 품질 검사와 탐색적 분석
- 예측용 데이터셋 생성 코드
- 현재값 유지 기준 모델
- 학습한 머신러닝 모델과 비교 결과
- 저장된 모델을 사용하는 FastAPI
- 관측값과 예측값을 확인하는 웹 화면
- 실행 방법, 실험 결과와 한계를 설명하는 문서

위 항목은 계획이며, 현재 구현 완료를 의미하지 않는다.

## 7. 기상 참고 지표의 범위

추후 예측 파고가 설정한 임계값을 넘는지 화면에 표시한다.

이 표시는 기상 상태를 이해하기 위한 참고 지표다.
실제 사고 확률이나 해군 임무 수행 가능성을 예측한 결과는 아니다.

예측값과 실제 관측값을 구분하고,
예측 기준시각과 예측 대상시각을 함께 표시한다.

## 8. 첫 버전에서 제외하는 범위

- 모든 해역으로의 일반화
- 72시간 장기 예측
- 실제 사고 확률 및 임무 성공 가능성 예측
- 딥러닝 모델의 필수 도입
- 자동 재학습 및 자동 모델 교체
- 별도의 GPU 추론 서버

## 9. 완료 기준

- 데이터에서 예측 결과까지의 과정을 다시 실행할 수 있다.
- 입력, 정답, 전처리와 데이터 분리 방법을 설명할 수 있다.
- 기준 모델과 머신러닝 모델을 동일한 조건에서 비교한다.
- 성능이 좋은 경우와 실패하는 경우를 분석한다.
- 저장한 모델을 API와 웹 화면에서 사용할 수 있다.
- 구현 상태, 테스트 결과와 미검증 항목을 구분해서 기록한다.

기준 모델보다 좋은 성능을 보장하지 않는다.
개선되지 않은 경우에도 실험 결과와 가능한 원인을 기록한다.

## 10. 개발 환경

- Python: 3.13 계열
- 환경 및 의존성 관리: uv
- 개발 도구: pytest

### 환경 구성

프로젝트 루트에서 실행한다.

```bash
uv sync --python 3.13
```

### 환경 확인

```bash
uv run --locked python --version
uv run --locked python -m pytest --version
uv lock --check
```

위 명령은 환경 확인용이며, 프로젝트 테스트 실행을 의미하지 않는다.

### 패키지 확인

```bash
uv run --locked python -c 'import marine_forecast; print(marine_forecast.__file__)'
```

개발용 editable 설치에서는 현재 저장소의
`src/marine_forecast/__init__.py` 경로가 출력되어야 한다.
소스 코드는 이 경로에서 사용하며, 빌드 설정이나 의존성을 수정했다면
`uv sync`를 다시 실행한다.

### 테스트 실행

```bash
uv run --locked python -m pytest -v
```

현재 테스트는 다음 두 가지를 검증한다.

- 패키지 import가 현재 저장소의 소스 파일을 가리키는지 확인한다.
- 프로젝트 밖의 임시 디렉터리에서 별도의 Python 프로세스로 import해도
  같은 소스를 사용하는지 확인한다.

두 번째 테스트는 Python의 `-I` 옵션으로 현재 작업 디렉터리와
`PYTHONPATH`의 영향을 제외한다. 두 테스트 모두 개발용 editable 설치를
대상으로 하며, 배포용 wheel 설치를 검증한 것은 아니다.

`pyproject.toml`과 `uv.lock`은 Git으로 관리한다.
로컬 가상환경인 `.venv`와 테스트 캐시는 Git에 포함하지 않는다.
